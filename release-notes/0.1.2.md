# Garmin Trainer 0.1.2

Status: prepared

Unsigned and not notarized; macOS may refuse to open this app.
Existing databases require the matching source CLI, a stopped owner and verified backups; startup never upgrades them.
Bundled notices are not redistribution authorization.

## Bugfix release for macOS Apple Silicon

0.1.2 follows 0.1.1 with one product fix and its supporting storage change. Platform, distribution profile and setup are unchanged: macOS ARM64 only, a DMG containing Garmin Trainer.app for manual placement, no installer, updater or background service. See the 0.1.1 notes and docs/release.md for download, setup, privacy and integration limits, which still apply.

### Fixed

- **Deleting a chat no longer erases saved cross-chat memory.** Ordinary chat or message deletion now refreshes history/source state only. The saved generated summary, your preferences, the summary frontier and the pins of surviving chats stay usable. This deliberately keeps what the deleted chat had already contributed to the summary; **Clear saved memory** remains the action that removes it. Bulk Chat/Profile reset and other source edits still revoke the generated summary as before.
- **Lost coverage is now shown durably.** When a genuine revocation empties a nonempty summary, Memory keeps a coverage-lost status across restart, retry and later new-only publications until Clear or a completed reviewed Update from chat history settles it.

### Added

- **Bounded local debug revisions.** The database keeps at most the 50 newest committed generated-memory revisions and at most 50 metadata-only deletion/revocation events, for explicit local SQLite debugging. Nothing in chat, pins, generation, import or rebuild reads them. Preference text is never archived. Source deletion/update and a direct summary save purge earlier payloads; Clear removes all of them. This is not a recovery feature: already erased memory is not restored, and physical SQLite pages, backups and provider logs are outside this guarantee.

### Database schema 27 and existing data

This release moves the database schema from 26 (0.1.1) to **27**. The change is additive: new control columns, two empty debug tables and re-created triggers; no existing rows are transformed. **A 0.1.1 database is refused by 0.1.2 until it is explicitly upgraded, and a schema 27 database is refused by 0.1.1.** Native startup and Use existing data never migrate.

Upgrading is the same advanced matching-source CLI operation as before: obtain the exact source commit recorded with this release and its dependencies, stop every writer, verify a WAL-consistent backup, rehearse `npm run db:migrate` on a disposable copy, and only then separately decide on the real target. Keep the 0.1.1 app and the pre-upgrade backup: recovery is that compatible pair or a forward fix, never a downgrade of an upgraded database or a blind copy-back over newer writes. Fresh databases created by 0.1.2 start at schema 27. See docs/release.md for the full procedure.

### Evidence boundary

Release readiness requires exact-source native tests, final-DMG verification and isolated authored-synthetic navigation/save/restart plus keyless Memory lifecycle evidence. The schema upgrade is covered by authored populated 26→27 regression tests, not by any real user database. None of this certifies a clean machine, minimum OS, Gatekeeper acceptance, the installed/default singleton, trusted hardware input, real Garmin login/sync, real browser authorization, paid providers or remote model quality. Actual test results and asset identities belong to the final release record and approval evidence, not this preparation status.

### Dependency findings and limits

Dependency versions, bundled Node/runtime inputs and the accompanying third-party source/notice corpus are unchanged from 0.1.1; only the application's own version changed. Findings were refreshed for this cut. The locked npm review still reports 21 development-graph findings (16 moderate, 5 high) and zero production-only npm findings. The OSV query over the 251 native registry packages in the macOS ARM64 build closure returned no matches. Querying every registry package in the lock file additionally matches five advisories in Linux-only crates (glib 0.18.5, proc-macro-error 1.0.4, zbus_names 4.3.5, zvariant 5.15.1, zvariant_derive 5.15.1) that are not part of this target's build closure and are not compiled into the app. Of the 10 locked external auth Python packages, garminconnect 0.3.2 still matches the high-severity permissive token-file creation advisory GHSA-wjhr-76vg-2hvc (fixed upstream in 0.3.5); the 0.1.1 mitigation is unchanged: desktop backend and auth worker use umask 077, native creates owner-private auth staging, and token publication verifies private permissions. That mitigates the creation exposure on the desktop paths without changing the reviewed integration pin; it does not repair previously exposed external token stores or certify separately resolved integration dependencies. These scans do not cover Node's embedded dependencies or precompiled C/C++/Wasm components.
