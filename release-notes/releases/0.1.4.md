# Garmin Trainer 0.1.4

Status: prepared

Unsigned and not notarized; macOS may refuse to open this app.
Existing databases require the matching source CLI, a stopped owner and verified backups; startup never upgrades them.
Bundled notices are not redistribution authorization.

## Changes

### Added

- The trainer can now analyse more of your Garmin data in chat: sleep sub-scores and timing, HRV weekly average and baseline, dated VO2 max readings, daily and per-activity Body Battery with its events, stress time per level, per-lap heart-rate zones, running cadence/stride and other running dynamics, and snowboarding run/lift totals. New syncs import them automatically. Missing data is reported as missing, not as zero.
  - Requires the explicit database upgrade to schema 29 (`npm run db:migrate` on a backed-up, stopped database); older builds refuse the upgraded database.
  - Existing history gains these fields only through the separate explicit `npm run backfill:garmin-extra` maintenance run with a fresh Personal API key; see `docs/garmin-extra-data.md` for backup, rehearsal and recovery.
  - Snowboarding values are per-type totals (all runs together), not individual runs. Advanced running dynamics appear only when a compatible sensor recorded them.

- Trainer analytics can compare individual measured ski/snowboard runs separately from lifts, with source duration, distance, speed, descent and honest import coverage. Per-type totals remain separate; run heart rate is unavailable without a proven lap link.
  - Existing data requires explicit schema-30 migration and the separately authorized `backfill:garmin-extra --snow-only` operation, after a verified recovery backup and full-history disposable rehearsal. Source delivery never automatically upgrades or backfills the primary app.

- Health and Activity now show more of your stored Garmin data, read-only and without starting a sync (T0357 / PR #242).
  - Health (Daily): Garmin's HRV baseline range, sleep-score qualifiers, a stress breakdown in minutes, Body Battery charged and drained, and dated VO2 max readings. Missing values say whether Garmin returned none, the source was unavailable, the read failed or it was never imported; nothing is filled in or averaged.
  - Activity: signed Body Battery change, cadence and stride with their Garmin sources and units, an HR-zone column in the lap table, and snowboard run and lift totals plus the individual runs and lifts when they have been imported.
  - Data is unchanged, nothing needs migrating, and reverting the app version is the rollback.

### Changed

- Training Plan shows the section label next to the page title when space allows. Smaller navigation and return buttons leave more room for plans, charts, and other content.

- Release notes are now written per change in `release-notes/unreleased/` and promoted into the next version's note by `npm run release -- prepare`, which removes only the fragments it published. Published version notes moved unchanged to `release-notes/releases/` (T0349 / PR #229).
  - Maintainer action: run `npm run release:notes:preview` before a cut and review the generated text. `--notes` is now optional reviewed text placed before the generated changes.

- Garmin now connects only through Garmin's official Personal API. Create a Personal API key in Garmin Connect, paste it in **Settings → Garmin connection**, Save, then quit and reopen. The key is stored privately on this device and never shown again. Existing installations show **Reconnect needed**: saved history stays available offline and old token files are left untouched. Activity details and exact heart-rate time in zones come from each activity's original file, and ended days become final when Garmin reports whole-day coverage (T0351).

- Ordinary trainer coaching can discover stored Garmin sleep score and qualifier, weekly HRV and baseline, daily Body Battery charged/drained and high-stress minutes in its recovery preview. Known-activity feedback also receives activity battery delta, source-labelled cadence/stride, historical lap heart-rate zones and snowboarding per-type totals, with missing-data coverage and explicit limits.
  - Consumes existing normalized extra-data fields; this consumer change adds no import, migration, primary activation or backfill. The build still needs a database matching its current schema. Older history without those fields remains explicitly unknown, not zero. Individual snow runs/lifts are not part of this change.

- The activity detail's individual snow table now shows runs only, with timer duration, distance, ascent/descent and measured average/max speed. All admitted runs are available beyond the previous 60-entry limit, and preserved runs carry an honest latest-coverage warning. Existing per-type totals remain separate (T0359 / PR #243).

- The project's own code and assets are now available under the MIT License, including earlier versions such as 0.1.1–0.1.3. Future builds carry the license as `FIRST-PARTY-LICENSE.txt`. Dependencies, the ChatGPT logo, Garmin names and map data keep their own terms (T0360 / PR #247).

- Health now shows Deep, Light and REM sleep together in one stacked-bar card in Daily, Weekly and Monthly (T0361 / PR #244).
  - Bars stack REM at the bottom, then Deep, then Light. Point to, focus or tap a date or period to read each stage and the independently recorded sleep duration; the order is a display choice, not a ranking of sleep quality.
  - Awake and Nap stay separate charts, as does sleep score. Missing stage values are never drawn as zero: an incomplete night shows no stack but keeps every known value, and Weekly and Monthly keep their existing per-stage daily averages.
  - Data is unchanged, nothing needs migrating, and reverting the app version is the rollback.

- Activity details no longer show Max cadence, list metrics are titled simply Cadence and Stride length, and run/lift sections appear only on ski and snowboard activities that actually have stored totals or runs.

- Chat conversations are now chosen from a left-side selector that collapses and expands with its own arrow, like Activities, at both wide and narrow window sizes. The separate Conversations menu button and the narrow-window conversation drawer are gone; your chats, drafts and selection are unchanged.

- Snow activity runs now show an average heart rate and an HR-zone bar (with exact times) for each measured run, derived from the stored heart-rate samples during that run; they may differ slightly from Garmin per-lap totals, and show a reason instead of a number when samples or the activity's own zone limits are missing (T0365).
  - Runs and lifts totals are one compact line, run Ascent is no longer shown, and the redundant Lap details table is hidden for snow activities that have individual runs; other activities and snow activities without runs keep their laps.
  - The trainer can use the same per-run and per-lift heart rate for known activities. Nothing is stored or imported: existing history shows it immediately where samples exist.

- Snow runs with at least 80% measured HR coverage can now show supported-only average HR and zone times despite long gaps. Rows show measured duration coverage and gap warnings; trainer run/lift evidence carries the same limits. Missing time is never filled, low coverage remains unavailable, and missing activity-file zone limits still leave zones unavailable (T0367 / PR #251).

### Fixed

- Sync latest can finalize eligible past health dates using verified upload evidence when the selected watch's direct timestamp is unusable (T0345 / PR #225).

- Garmin Sync no longer fails a whole month of sleep, HRV, stress and Body Battery data when Garmin includes an undated nap-only sleep entry; that entry is skipped and every dated day is imported.

- Existing snow history can now show sample-derived run heart rate when its stored UTC clock is proven by the activity start, using consistent historical activity-file zone limits. Unsupported runs explain the missing time, HR support or zone-limit evidence instead of misleadingly saying there are no HR samples. No re-import or stored-data rewrite is needed; sparse runs can still be unavailable.

- Resort skiing and snowboarding activity navigation shows recorded runs distance without lift travel, or a dash when unavailable. Session duration is unchanged.

- A momentary ChatGPT connection interruption during the connection currentness check no longer marks a working ChatGPT account as disconnected; the check retries one transient failure within its original deadline and still requires current confirmation.

### Removed

- The app no longer needs Python, uv or uvx, and no longer asks for a Garmin email, password or MFA code. The unofficial Garmin connector, its sign-in flow, the terminal `garmin:auth` command and the related tool settings are removed (T0351).

- Removed the manual Reload history action from conversation menus; chat history continues to load automatically. (T0364)

### Internal

- Adds a tested but **inactive** foundation for reading Garmin through its official Personal API: bounded HTTPS and key exchange, in-process activity-file decoding with exact HR time in zones, range-based daily/history/discovery reads, and whole-day coverage finality. Sync still uses the existing connector; nothing changes for current users until the separate cutover (T0351 / T0350).
