## First macOS Apple Silicon release

Garmin Trainer is a local, single-user desktop training companion. It imports Garmin activity and health history, displays activity/health trends, and offers streaming coaching with guarded read-only SQL/math tools. Profile, General Plan, weekly plans/reviews and cross-chat memory have separate persistence and privacy controls. Direct OpenAI/DeepSeek, explicitly configured Ollama/OpenRouter, and optional ChatGPT subscription routes retain their own access and privacy requirements; no account or real-service certification is implied.

### Download and setup

This release targets macOS ARM64 only. The DMG contains Garmin Trainer.app; manually copy it to an explicitly chosen Applications location. There is no installer, updater or background service. Node/Next/SQLite are bundled; normal launch does not require system Node, Rust or a checkout. Garmin actions require separately managed uv/uvx and compatible Python (native sign-in: installed Python 3.12); optional Ollama requires its separately managed daemon/model. The app installs none of these tools or models. Configure native Settings explicitly, then create fresh data or select an already-compatible database. Startup and Use existing data never migrate a database.

Unsigned/non-notarized software may be refused by Gatekeeper or organizational policy. Do not disable Gatekeeper, strip quarantine or change system trust. Minimum macOS 12.0 is a declared target, not a tested minimum-OS or clean-machine guarantee.

### Privacy and integration limits

Use only on loopback, never a LAN/public host or tunnel. Cloud providers receive selected chat/Garmin context. Private settings and optional subscription credentials are owner-private plaintext, not encryption; same-user/privileged processes and backups can read them. Keep settings, tokens, databases, debug traces and screenshots private. Garmin uses a pinned unofficial connector; endpoint, challenge, rate-limit and availability changes may break it. Coaching is not a guarantee of accuracy or a substitute for professional judgment.

### Existing data and recovery

Existing-data upgrades are advanced matching-source CLI operations: obtain the exact source commit recorded with the release and its dependencies, stop every writer, verify a WAL-consistent backup and rehearse on a disposable copy before separately approving the real target. Native startup never upgrades existing data. Preserve prior compatible app/source/DB/settings and newer writes; recover with a compatible forward fix or separately reconciled compatible restore, never automatic downgrade or blind copy-back. See docs/release.md for the full procedure.

### Dependency findings and limits

The locked npm review reports 21 development-graph findings (16 moderate, 5 high) and zero production-only npm findings. This does not scan Node's embedded dependencies or establish that precompiled C/C++/Wasm components are vulnerability-free. The current OSV query covered 251 native registry packages and 10 locked external auth Python packages; it matched garminconnect 0.3.2 to the high-severity permissive token-file creation advisory GHSA-wjhr-76vg-2hvc (fixed upstream in 0.3.5). Desktop backend configuration and the auth worker set umask 077, native creates owner-private auth staging, and token publication verifies private permissions. The backend mask is inherited by connector/FIT descendants; a regression starts from umask 022 and verifies private creation without altering existing files. This mitigates the reported creation exposure on the desktop paths without changing the reviewed integration pin. It does not repair previously exposed external token stores or certify every separately resolved integration dependency. No private credentials or existing stores were inspected or rotated for this release.
