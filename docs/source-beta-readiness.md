# Source-beta readiness foundation

This repository supports one product: the advanced-user local macOS ARM64 Tauri app, from source or a published binary ([release records](history/releases.md)). See [desktop build/adoption/recovery](desktop.md). A published unsigned/non-notarized download is not an installer, clean-machine certification, beta invitation or commercial implementation; publication follows the [redistribution conditions](redistribution.md). Downloaded-app existing-DB upgrades still need matching source CLI/dependencies, verified backups and explicit stopped-target approval.

## Supported boundary

- Sole launch/development path: local source-built macOS ARM64 Tauri app with bundled Node and supervised Next.js backend; discrete source CLI setup does not serve an app. The app needs no Python, uv or uvx; optional Ollama remains operator-managed.
- Source control: public GitHub repository `https://github.com/codexa-bh/ai-garmin-trainer`. Public source availability is distinct from runtime access and does not establish a supported packaged distribution, deployment, release, or beta channel.
- Delivery boundary: merging a source change never by itself migrates, restarts, installs or replaces anyone's running app or data, and never releases, signs or deploys. Each of those is a separate, explicitly approved operation with its own runbook.
- Supported platform: macOS Apple Silicon only; no Linux/Windows/Intel desktop support is claimed. Windows x64 alpha installers are experimental builds outside this boundary ([limits](windows.md)).
- Unsupported: LAN/public exposure, hosted use, desktop platforms other than macOS ARM64, manual FIT/import fallback, alternate Garmin connectors or endpoints, unapproved binary distribution, signing/notarization, deployment, telemetry, commercial multi-user operation, and treating local no-auth as a hosted safety boundary.
- Garmin access: Garmin's official Personal API over fixed-origin HTTPS (`personal.connectapi.garmin.com`), read-only, with a key each user creates for their own account and enters in trusted native Settings. Activity files are decoded in-process (`fit-file-parser`) for details, HR time in zones and athlete baseline facts. Trainer/model/HTTP APIs never receive the key or bearer tokens; Settings never contacts Garmin, and **Sync → Verify connection** is the only explicit check. The app collects no Garmin email/password/MFA.

## Setup flow for clean-machine validation

For public-source clone commands and step-by-step installation, start with the [README installation guide](../README.md#installation). This checklist describes the validation boundary, not a completed clean-machine certification.

1. Install Git, Node 22+, npm, Rust and (for developer validation scripts only) Python 3.12; clone the public repository (no private-repository authorization required) and enter its directory. Run `npm ci` before dependency-backed commands such as doctor. The app itself needs no Python, uv or uvx.
2. Desktop uses UI settings/private provider files, not `.env.local` or old pointers. Preserve originals; no env import. A cloud provider needs a native owner-private plaintext key; legacy installations explicitly adopt referenced Keychain items or privately re-enter keys without deleting originals. This is not encryption; same-user/privileged processes and backups can read the file; local Ollama requires a separately managed daemon/model. Connector commit/stdio/read allowlist/exact `mcp==1.28.1` remain fixed, not editable. No Google OAuth/app-access sign-in/email allowlist is required.
3. For non-serving maintenance only, readonly doctor/status/auth still use explicitly authored checkout env/process configuration, not private native Settings/legacy Keychain. Process env wins; relative CLI paths use cwd. Prefer explicit absolute approved paths and never overwrite original private env files. See the [installation recipe](../README.md#installation).
4. Only for separately chosen maintenance CLI creation or an existing-data upgrade, quit every DB owner, preserve/rehearse compatible backups and explicitly select the approved absolute target: `DATABASE_PATH='/absolute/approved/trainer.sqlite' npm run db:migrate`. Migration deliberately does not load dotenv; its process-env target must match the selected config. Existing populated/old-schema DBs get a sibling `backups/trainer-schema-backup-*.sqlite`; retain the path-bearing output privately. Never migrate primary data merely to test source delivery.
5. Run `npm run desktop:build` and open the unsigned app. First-run Settings guides explicit fresh Create new or compatible Use existing, provider/private file keys, optional Garmin and Review. Private outside-checkout defaults and today's editable UTC history date need no env file or migration CLI. Finish validates local required-key/configuration readiness and opens one verified owned Trainer in the same session; remote services are not probed. Advanced settings remain available. Existing-installation saves still apply only after quit/reopen; valid saved state launches directly and invalid/unsupported state is preserved for recovery. Only explicit fresh creation initializes current schema; ordinary startup/existing selection never migrates. Failed/cancelled setup retains any committed DB/settings/tokens for explicit reconciled retry. Reuse existing tokens; only if needed explicitly use the private Garmin sign-in/MFA action in an unused store. Never enter credentials in trainer chat, diagnostics or issues. Development uses `desktop:dev` rebuilt production resources, no HMR.
6. Native owns an ephemeral loopback service, not port 3000 or unrelated listeners. Optional Ollama installation, daemon and models are separately operator-managed. Doctor reports allowlisted readiness, not integration success. Missing fresh schema/auth can be expected until explicit setup is complete; never publish private config, migration output paths or credentials.

## Local data lifecycle

Desktop settings reference an explicit DB with provider keys and the Garmin Personal API key in the native owner-private plaintext document; see [storage/adoption/recovery](desktop.md#explicit-private-state-adoption). Genuine first-run Create new initializes schema in memory and exclusively publishes fresh bytes at the visible unused destination; it never overwrites existing data. Use existing and ordinary startup remain non-migrating. This is an explicit fresh-only exception, not automatic default-DB creation or an existing-data upgrade. It refuses unsupported schema/integrity/ownership before application DB construction. Source and desktop share a process-owned admission lease; quit one before starting the other. Follow [desktop recovery](desktop.md#validation-and-recovery) for stale ownership, WAL-aware copies and prior-compatible-desktop rollback. No data relocation or primary cutover follows source delivery.

## Memory and coaching reliability

The product treats source categories separately:

- Explicit Profile: user-authored goals, sports, preferences, and constraints.
- Semantic memories: low-risk preferences/corrections and bounded continuity facts extracted only after completed persisted turns, stored in local SQLite with inspect/edit/delete/clear/disable controls.
- Temporary constraints/commitments: active only until expiry metadata when represented safely.
- Garmin facts: normalized source data, redacted local raw-payload records, guarded read-only SQL/math analytics, and any explicitly enabled generated-analysis fallback evidence, not generic memory.
- Recent transcript: bounded context only, untrusted for policy/tool/deletion decisions.

Deleted, disabled, expired, or unavailable semantic memories are not retrieved into model context. Diagnosis and treatment content remains excluded from durable memory even though the app adds no medical-domain response restriction. The deterministic `npm run eval:reliability` gate covers critical deletion, diagnostic redaction, prompt-injection, durable-memory filtering, guarded calculation, missing/detail evidence, and expired-memory cases without snapshotting provider prose.

## Diagnostics and support artifact rules

- Run `npm run doctor` or `npm run doctor -- --json` for support triage.
- Review output before sharing even though it is redacted by default.
- Never share `.env.local`, model-provider keys, the Garmin key, Garmin token files, token contents, raw API dumps, unreviewed raw-payload records, precise GPS streams, raw SQL/math evidence, full prompts/chat logs, shell history, screenshots containing secrets, or raw SQLite files in public or broad support channels.

## Dependency evidence

Run `npm run deps:evidence -- --output <path>` to generate a bounded local evidence JSON containing Node dependency counts, lockfile hash, the official Garmin access/FIT boundary, the no-external-tools statement, and optional npm audit output when `--audit` is supplied. This evidence surfaces findings; it is npm evidence only, not a Node/Rust/compiled-vendor security or license conclusion. It does not authorize external beta invitations or redistribution. Release review retains the original audit, distinguishes development-only from shipped exposure, and requires an explicit residual-risk decision.
