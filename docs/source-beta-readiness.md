# Source-beta readiness foundation

This repository supports advanced-user source operation and a locally source-built macOS ARM64 desktop runtime. See [desktop build/adoption/recovery](desktop.md). This is not a distributed installer, clean-machine certification, public release, beta invitation, provider application, deployment or commercial implementation.

## Supported boundary

- Primary paths: local MCP-only advanced-user source setup and local source-built macOS ARM64 Tauri app with bundled Node; external uv/Python and optional Ollama remain operator-managed.
- Source control: public GitHub repository `https://github.com/codexa-bh/ai-garmin-trainer`. Public source availability is distinct from runtime access and does not establish a supported packaged distribution, deployment, release, or beta channel.
- Platforms prepared here: macOS Apple Silicon first; Ubuntu LTS after reproducibility evidence.
- Unsupported: LAN/public exposure, hosted use, desktop platforms other than macOS ARM64, manual FIT/import fallback, alternate Garmin connectors, packaged distribution/signing/notarization, deployment, release, telemetry, commercial multi-user operation, and treating local no-auth as a hosted safety boundary.
- Garmin connector: `Taxuspt/garmin_mcp` pinned to `3610be6feed93088d85b0f35aba9d7d07c2505a7` with exact `mcp==1.28.1`, launched over local stdio only, with app-side read-operation allowlisting. A local read-only FIT baseline helper may use the same out-of-band Garmin token store to extract only approved `zones_target` max-HR facts from recent activity FIT files. Garmin auth remains out of band through `garmin-mcp-auth`; the app checks auth-state file presence only and never reads token contents.

## Setup flow for clean-machine validation

For public-source clone commands and step-by-step installation, start with the [README installation guide](../README.md#installation). This checklist describes the validation boundary, not a completed clean-machine certification.

1. Install Git, Node 22+, npm, and Python 3.12-capable `uv`/`uvx`; clone the public repository (no private-repository authorization required) and enter its directory. Run `npm ci` before dependency-backed commands such as doctor or Garmin auth. The app uses `uvx` for the pinned Garmin MCP subprocess and `uv run --with garminconnect --with fitparse` for the local read-only FIT baseline helper.
2. Copy `.env.example` to `.env.local` for a new checkout (preserve existing configuration); fill `DATABASE_PATH`, pinned Garmin MCP settings, and your chosen chat provider configuration. A cloud provider needs its matching key; explicit loopback Ollama chat needs a separately installed/running daemon and the chat model pulled first. Keep the Garmin MCP args' exact `--with mcp==1.28.1` requirement; it matches the reviewed connector's current MCP 1.x dependency floor while avoiding MCP SDK 2.x, which removes the `mcp.server.fastmcp` import path used by the connector. No Google OAuth, app sign-in secret, or email allowlist is required for private loopback use. Configure the single `GARMIN_MCP_TOKEN_DIR` and follow [Garmin setup/recovery](garmin-auth.md), reusing existing credentials before operator-run `npm run garmin:auth`. Never paste Garmin passwords, MFA codes, tokens, cookies, or token file contents into the app, chat, diagnostics, or support issues.
3. Run `npm run bootstrap:local`. It uses the committed lockfile to install project dependencies when `node_modules` is missing/stale, runs `npm run db:status -- --json` and invokes `npm run db:migrate` only for missing/outdated schemas, builds, runs doctor, and starts or reuses the verified loopback app. If semantic memory is enabled with Ollama, it reuses a healthy loopback daemon, starts `ollama serve` only when absent, pulls only the exact configured missing model, and proves a real embedding response. It never installs Node, Python, uv/uvx, Ollama, package managers, launch agents, services, or Garmin tooling.
4. Manual recovery remains available: run `npm ci` first, then `npm run doctor -- --json`, `npm run db:status -- --json`, `npm run db:migrate` when status says migration is needed, `npm run build`, and `npm run start:local`. On a fresh setup, doctor may report missing schema/auth state until preparation is complete; recheck afterward. Doctor output is allowlisted: versions, config presence booleans, schema/integrity state, connector pin/auth-state presence, provider key presence, and loopback posture. It does not print credentials, token contents, provider keys, prompts, precise GPS streams, or raw connector payloads.
5. Existing SQLite files are copied to `data/backups/trainer-schema-backup-*.sqlite` only by the migration path; ordinary current-schema bootstrap starts skip migration to avoid redundant backups.
6. The supported production-local command binds Next.js to `127.0.0.1:3000` by default. For local port conflicts, repeat restarts may use `npm run restart:local -- --port <port>` or `AI_GARMIN_RESTART_PORT=<port>` while still binding only to `127.0.0.1`. LAN/public host binding is unsupported and flagged by doctor/bootstrap.

## Local data lifecycle

Desktop adoption references an explicit existing private env/DB; it never invokes bootstrap/migration or creates a default blank DB. It refuses unsupported schema/integrity/ownership before application DB construction. Source and desktop share a process-owned admission lease; quit one before starting the other. Follow [desktop recovery](desktop.md#explicit-private-state-adoption) for stale ownership, WAL-aware copies and source rollback. No data relocation or primary cutover follows source delivery.

| Operation               | Source-beta behavior                                                                                                                                                                                                                                                                                                                                         |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Schema upgrade          | `npm run db:status -- --json` reports whether migration is needed without backing up current-schema databases. `npm run db:migrate` records explicit schema version in `app_metadata`, creates/updates tables, backs up existing user-data databases before upgrade, and verifies integrity. Bootstrap calls migration only when status is missing/outdated. |
| Restore                 | Stop the app, replace `DATABASE_PATH` with a backup SQLite file, run `npm run db:migrate`, and run `npm run doctor -- --json`. Automatic downgrade is not supported; pre-upgrade backups are the rollback boundary.                                                                                                                                          |
| Export                  | No one-click product export exists yet. For clean-machine validation, export is a manual SQLite copy after stopping the app. Exports must exclude `.env.local`, provider keys, Garmin token files, shell history, and diagnostics unless explicitly reviewed.                                                                                                |
| Clear chat/profile      | Deletes conversations, messages, and explicit profile. It preserves semantic memory and normalized Garmin data; use Clear all memory for semantic memory.                                                                                                                                                                                                    |
| Delete Garmin data      | Deletes app-managed normalized Garmin rows, detail tables, redacted raw-payload records, sync runs, and checkpoints. It does not delete external Garmin token files.                                                                                                                                                                                         |
| Garmin disconnect/reset | Stop the app, optionally delete app-managed normalized Garmin data, then manually remove the app-owned `GARMIN_MCP_TOKEN_DIR` or upstream `~/.garminconnect/garmin_tokens.json` if the user chooses to reset Garmin auth.                                                                                                                                    |
| Backup                  | Copy SQLite only after stopping the app and remember it may contain redacted local Garmin raw-payload records. Do not bundle model-provider keys, Garmin token contents, prompts, raw connector dumps, unredacted raw payloads, or precise GPS streams into support artifacts.                                                                               |
| Uninstall               | Stop `npm run start:local` or the foreground `npm run bootstrap:local` session, remove the source/worktree directory, optionally remove SQLite data/backups, optionally remove app-owned Garmin token directory, and remove `.env.local`/provider keys. No background service or launch item is installed by this source-beta path.                          |

Weekly plans/reviews (schema 16) are independent user documents: migration creates empty additive storage and does not fabricate commitments or alter the General Plan. Confirmed artifacts survive both chat/Profile clearing and Garmin deletion; pending proposal authority is cleared with its conversation. No new artifact deletion scope is provided. Back up before adopting the new schema; automatic downgrade is unsupported and a pre-upgrade backup remains the rollback boundary. No Garmin re-sync/backfill is required for this document-only migration.

## Memory and coaching reliability

The product treats source categories separately:

- Explicit Profile: user-authored goals, sports, preferences, and constraints.
- Semantic memories: low-risk preferences/corrections and bounded continuity facts extracted only after completed persisted turns, stored in local SQLite with inspect/edit/delete/clear/disable controls.
- Temporary constraints/commitments: active only until expiry metadata when represented safely.
- Garmin facts: normalized source data, redacted local raw-payload records, guarded read-only SQL/math analytics, and any explicitly enabled generated-analysis fallback evidence, not generic memory.
- Recent transcript: bounded context only, untrusted for policy/tool/deletion decisions.

Deleted, disabled, expired, or unavailable semantic memories are not retrieved into model context. Diagnosis and treatment content remains excluded from durable memory even though the app adds no medical-domain response restriction. The deterministic `npm run eval:reliability` gate covers critical deletion, diagnostic redaction, prompt-injection, durable-memory filtering, guarded calculation, missing/detail evidence, and expired-memory cases without snapshotting provider prose.

## Diagnostics and support artifact rules

- Run `npm run doctor` or `npm run doctor -- --json` for support triage.
- Review output before sharing even though it is redacted by default.
- Never share `.env.local`, model-provider keys, Garmin token files, token contents, raw connector dumps, unreviewed raw-payload records, precise GPS streams, raw SQL/math evidence, full prompts/chat logs, shell history, screenshots containing secrets, or raw SQLite files in public or broad support channels.

## Dependency evidence

Run `npm run deps:evidence -- --output <path>` to generate a bounded local evidence JSON containing Node dependency counts, lockfile hash, Garmin MCP pin, exact `mcp==1.28.1` compatibility requirement, transport/auth boundary, Python/uvx dependency boundary, and optional npm audit output when `--audit` is supplied. This evidence surfaces blockers; it is not a legal/security/license conclusion and does not authorize external beta invitations or redistribution.
