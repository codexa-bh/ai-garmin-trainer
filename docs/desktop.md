# Local macOS desktop runtime

The source-built **macOS Apple Silicon** app is a thin Tauri host with an owned loopback Next.js service. React, HTTP/NDJSON, Next `after()`, guarded tools, SQLite and connector policies remain the application, not a remote website wrapper or Rust domain rewrite. Default launches grant native commands only to the local settings document, never trainer/remote pages. An explicitly admitted isolated ordinary-artifact or debug smoke instance has only its exact-origin correlated-result callback, never settings/auth privileges; see [programmatic smoke](dev-bridge.md).

Local unsigned builds only: no signing/notarization, installer/release channel, auto-update, login item or background service. Public source grants none of these operations. Intel, Windows, Linux and universal bundles are unsupported.

## Build and run

Build prerequisites: ARM64 macOS, Xcode/Command Line Tools, Rust/Cargo and Node 22/npm. Runtime integrations need separately managed uv/uvx and Python 3.12; optional Ollama is external. No Python/software/model installation or Ollama startup is performed by the app. Explicit integration use may acquire locked Python packages through uv.

```bash
npm ci
npm run desktop:build
```

Open `src-tauri/target/aarch64-apple-darwin/release/bundle/macos/Garmin Trainer.app`, including outside the checkout. `desktop:dev` uses the same rebuilt production resources, no HMR/browser dev server. Source edits require rebuilding; settings edits need only explicit quit/reopen. Tauri is the sole product launcher. Retained doctor/status/migration/private-terminal-auth tools are non-serving maintenance, not desktop configuration sources.

The native crate enables `custom-protocol` by default so local settings/error HTML works without a backend. Native Settings remains available from the **Settings…** native menu regardless of backend readiness. Startup status is persisted in memory to avoid listener races.

`desktop:build` passes `--no-sign --no-binary-patching`; no codesign/notarization runs. Do not disable Gatekeeper or install/sign to bypass errors. Keep release stripping disabled: Homebrew Rust 1.98 proc-macro metadata failed with release stripping (`E0463`); the supported no-strip build preserves compiler output.

A separate [change-gated nightly profile](validation.md#change-gated-native-nightly)
uses full validation's single backend build, assembler-only `desktop:assemble`,
locked Rust checks/tests and one synthetic `smoke:quick` debug run. It does not run
optimized release packaging or replace ordinary actual-artifact/integration smoke.
Only use assembler-only immediately after a same-input production build; existing
`desktop:resources` still builds then assembles.

### Reproducible resources

`scripts/desktop/runtime-inputs.json` pins Node 22.23.4 ARM64 and its official archive checksum. Assembly verifies it and probes bundled Node/SQLite ABI plus launcher imports. Cargo/npm locks pin their inputs; Tauri direct versions are exact.

Resources include production standalone output/static assets, the complete pinned production Next custom-server package, native SQLite, bundled launcher/Zod, four FIT Python helpers/token-location module, and the first-party `garmin_auth.py` plus its uv script lock. Auth uses reviewed `garminconnect==0.3.2` directly, not the upstream CLI. External uv/Python remain operator-owned. Private env/data/tokens/logs are never packaged. `provenance.json`, Node license and third-party notices accompany local builds; metadata is not redistribution authorization.

Resources are immutable: desktop disables ISR disk flushing/image optimization, bounds memory cache and disables Python bytecode writes. The trusted build configuration is installed through Next's standalone configuration path and retained across framework env reset; the custom-server wrapper does not forward its direct `conf` option to the router. Provider values never enter that serialized build configuration. Private state/WebView storage stays outside the bundle. The supervisor drains and discards incidental output, accepting only bounded allowlisted startup messages; vendor/framework stdout/stderr are not diagnostics.

## Explicit private-state adoption

**Settings** replaces env-file selection/loading entirely. Upgrades do not import the old pointer or env files. Users re-enter supported settings; originals are retained unchanged for rollback. No cwd/home/adjacent env discovery or generic environment editor exists.

- Genuine first run has Data → Provider → Connect Garmin or continue → Review steps. Explicit **Create new database** uses a visible unused owner-private app-data destination outside source/bundle; a custom destination needs an existing private parent. Bootstrap runs authoritative migrations in memory, then native writes/fsyncs/read-only verifies and exclusively publishes fresh bytes under a pinned parent descriptor/shared target lease. Existing files, sidecars, aliases and unknown leases are never replaced. No writable selected-file migration or initialization WAL is involved.
- **Use existing data** selects a compatible DB using a canonical absolute path. Garmin has Connect/continue/connect-later/reconnect actions, not directory controls; compatible saved token selections remain internal and unchanged. No aliases, shell expansion, URLs or relative paths. Selected DB will be writable: first quit other owners, evaluate on a disposable populated backup, and obtain separate approval before primary cutover.
- `settings-v3.json` under the canonical platform app-config directory for `com.codexa.garmin-trainer.desktop` stores `{version:3,fields,keys,chatCatalog}`: unrelated/legacy extraction fields, private raw OpenAI/DeepSeek/OpenRouter slots and a version-1 chat catalog. Entries use durable opaque IDs (not row positions), literal model IDs and optional names; maximum 32 entries, ID 80, model 256 and name 80 characters. Exact duplicate provider/model tuples and invalid defaults are rejected. Directory `0700`, file `0600`, current uid, regular single-link bounded (128 KiB) unaliased objects. Descriptor-bound reads and pinned no-follow parent traversal, exclusive staging/fsync and atomic rename protect publication. Pre-existing insecure objects are refused, not chmodded/adopted. This is **plaintext, not encryption**: same-user/privileged processes and backups can read it. No Garmin email/password/MFA or token contents. Never include this document in logs/support/export/Git.
- Normal settings cover DB/history, Garmin connection actions and add/edit/remove/default chat catalog controls for all four providers, with shared masked key slots. Token paths remain compatible internal configuration, never normal manual controls. No global chat auto/provider selector remains. Memory → Remember useful details provides On/Off independently of chat. Memory configuration expands embedding/extraction choices; Troubleshooting / technical controls retains dimensions, timeouts, five executable overrides, the Ollama connection and a read-only explanation of preserved extraction/title inputs. Complete values persist independently of disclosure/disabled state; invalid hidden inputs expand for correction. Off preserves records and the separate immediate Trainer disable preference. Explicit Read active memory status is setup-only, fixed and identity-bound to the owned backend; it returns metadata/recent existing scoped observations (60-second expiry), never memory content, new probes or provider requests. Saved/draft values are not active status; missing/stale observations remain unknown, not provider readiness. Shared application validators/defaults remain authoritative; native invokes bundled validation and readonly DB schema/integrity checks before private settings changes. No connector pin/args/transport/allowlist, port/origin/identity or arbitrary command/env controls are editable. Debug traces remain always enabled by tested policy; no misleading off toggle.
- Eligible first-run **Finish and open Trainer** validates required provider configuration before creation, commits DB/private settings separately, and uses the existing owned-backend readiness path in this session. No cloud probe, automatic login/sync or fallback. Native captures genuine settings absence once; crashed/invalid/unsupported existing installations do not gain first-run authority. Duplicate operations serialize natively. Cancel/quit is bounded; already committed DB/settings/independent tokens remain saved. Explicit retry reconciles exact DB identity or, after settings commit, opens only the committed configuration. After an interrupted DB-only commit/relaunch, explicitly choose that retained file as existing data.
- Ordinary **Save for next launch** still needs explicit quit/reopen. Cancellation/invalid saves preserve prior settings/current backend. Settings never switch an active DB/provider/account or restart the app. Trainer model preference remains independently persisted; configured default and saved preference are not conflated.
- Missing/corrupt/unsupported private settings or unavailable required provider keys reopen sanitized actionable settings. Unknown versions are not overwritten/downgraded. Preserve the record for recovery and use a compatible build; do not delete data, relax permissions or fall back to env files.

Presence selects v3 before v2 before v1, including corrupt, unreadable or aliased objects. Unknown/newer formats refuse overwrite/downgrade. Explicit Settings Save from v2 exclusively publishes v3 and indefinitely preserves original v2 bytes; startup derives only a read-only compatibility catalog until that action. Explicit old provider intent survives, including missing-key intent. Old auto projects its configured DeepSeek-first/OpenAI model when determinable, else no default; no continuing chat fallback policy. Catalog/default edits do not rewrite the old cloud extraction/title policy/models. Empty catalog/no default admits offline views with chat selection required; existing DB and enabled embedding-key admission remains binding. When only `settings-v1.json` exists, validate its allowlisted fields and `SLOT/UUID` account references without querying Keychain; startup reports migration-required and opens setup. This is not blank-install authority. Startup, menu refresh, ordinary Save and Finish never call Keychain, including metadata queries.

Choose **Adopt referenced Keychain keys once** in trusted local setup to read only referenced accounts under legacy service `com.codexa.garmin-trainer.desktop.provider.v1`. macOS may request permission; never bypass refusal or automate its dialog. Adoption serializes with settings/Finish/activation, resolves every unchanged legacy slot, validates the complete intended existing-activation frame through the bundled validator, then exclusively publishes v3 with the reviewed catalog. Optional provider slots must also resolve or be explicitly replaced/cleared; partial retrieval is discarded, never silently omitted or automatically retried. After denial/locked/missing values, privately replace or explicitly clear every legacy configured slot and choose **Save private re-entry without Keychain**. This action makes zero legacy reads. A keyless legacy document follows the same explicit action without secret reads.

Both actions preserve original v1 bytes and **all original Keychain items indefinitely**, even on success; there is no cleanup/deletion API. No env import, broad enumeration, cloud probe or background adoption exists. Cancel before publication leaves legacy authority intact. Rename is the single-document commit/selection point; an interrupted launch reconciles v3 without rereading Keychain. Postrename verification/directory-sync failure reports **committed, durability uncertain**, not rollback or retry permission. Metadata-only reads include a bounded file-identity/mtime/ctime/size revision; whole-form save/adoption compares the loaded revision under native serialization. Stale forms refuse without publication and require reload, including intervening key-only edits. Reload metadata before another explicit action. Concurrent changed targets refuse publication; no existing v3 is overwritten by migration. Deleting/downgrading v3 is unsupported recovery. Preserve it and original v2/v1/Keychain inputs; use a compatible catalog build/forward fix, not forced legacy fallback.

Reads return only fields/storage/slot status, never saved values/account payloads. Blank means unchanged; replace/clear require explicit intent and affect only the active v2 document. Ordinary writes stage a complete replacement and preserve prior bytes on precommit failure; next-launch-only semantics remain. For rollback, preserve v3 and original v2/v1/Keychain recovery inputs plus compatible data/backups. Use a compatible build or forward fix; never overwrite/downgrade settings or delete originals. Source revert grants no private cutover.

At startup native sends validated catalog metadata and keys in **one bounded private stdin frame** (activation v2; legacy read-only v1 remains supported) for its owned Node child, never argv, inherited secret environment, a generated env file, renderer readback or URL. Internal backend environment remains an adapter only. The pipe stays open after the frame for parent-death/liveness. Next's reset retains the validated snapshot; DB/identity checks fail closed if it changes. Provider keys are removed from ordinary MCP/FIT child environments.

Readonly existing-file/schema/integrity checks precede ordinary DB construction. Missing/corrupt/old/unsupported DBs are refused, never created/migrated by ordinary startup or existing selection. Only explicit eligible first-run Create new initializes a fresh target; it is not an upgrade/adoption path. Explicit backed-up source migration on a stopped approved target is separate. Source/desktop share `<database>.trainer-writer`; macOS also refuses another process holding the DB open, including older backends without a lease. Unknown/stale leases are never stolen. Inspect the exact owner; never kill listeners or delete a live lease to force admission.

Use SQLite online backup for active-WAL copies, verify integrity and retain pre-upgrade rollback data. No schema/backfill change is introduced here. Last-active conversation selection, saved chat, Profile, memory, Trainer preference and general/original/latest weekly documents remain in the selected SQLite DB. Conversation selection is independent of the fresh loopback origin: startup resolves a valid saved row (including one outside the sidebar page), otherwise the stable most-recent existing row. Empty startup creates nothing; use explicit New chat. Existing browser selection is not imported or read. Deletion scopes/interruption semantics are unchanged.

## Integrations and GUI execution

The cleared child environment uses fixed GUI tool search `/opt/homebrew/bin`, `/usr/local/bin`, `/usr/bin`. Overrides accept canonical absolute executable paths or the supported uv/uvx names, never shell text/relative commands. No terminal init scripts run. Missing tools degrade integrations, not offline saved views. Ordinary Garmin remains pinned commit `3610be6feed93088d85b0f35aba9d7d07c2505a7`, exact `mcp==1.28.1`, local stdio/read allowlist; no inherited password/email/file or provider-key fallback reaches MCP/FIT.

Compatible saved token selections remain exactly where they are; no forced login, relocation or directory discovery. **Configured — not verified** means saved metadata, not current authentication/expiry. Explicitly choose **Connect Garmin** or **Reconnect Garmin** in trusted native Settings; never enter credentials in trainer chat. Connect later preserves any saved connection and provider draft. Chat and saved/offline history remain available without Garmin, but fresh Garmin data requires a working connection. This desktop-only transient entry is the narrowly approved exception to the former no-password-in-app policy, not permission for model/HTTP/trainer credential access. The retained private-terminal CLI remains TTY-only and is not scraped by UI.

One native UUID-bound session runs the locked first-party adapter with private JSON pipes, a 180-second absolute deadline, one MFA submission and explicit cancel. Only allowlisted authenticating/MFA/verifying/success/failure states reach UI. Rejection, expired/incorrect MFA, unsupported/repeated challenges, tooling, network/service, rate limits, timeout and protocol failures do not auto-retry or bypass challenges. Password/email/MFA never enter argv/env/files/logs; controls/references are cleared promptly. Managed runtimes cannot promise perfect memory zeroization.

Native derives the platform app-data private root and safely creates or validates it using pinned no-follow parent descriptors, unchanged ownership/private permissions and fresh UUID names. No normal caller supplies a destination. Existing insecure/aliased/substituted objects refuse without chmod/adoption. Worker writes private native-owned staging and performs independent token login/profile-presence verification without emitting the profile. Native pins parent/staging identities, serializes cancel versus commit and atomically publishes with exclusive rename; stale events cannot commit after cancel. Compatible `garmin_tokens.json`/`garmin_tokens.base64` are `0600` in a `0700` directory. Failed/owned staging is cleaned; originals remain untouched. Success does not promise expiry/future availability. Only the matching successful session exposes **Use this verified connection** to select its published destination in the settings draft. The summary distinguishes verified-this-sign-in from pending Finish/Save/next launch. Continue to first-run Review/Finish, or Save then explicitly quit/reopen for an existing installation. Token publication is an independent committed result and is retained if later setup fails/cancels. It never changes a running import's account.

This is unofficial international Garmin login, not official OAuth or guaranteed challenge support; no new region/provider/CAPTCHA bypass. See [Garmin auth](garmin-auth.md) and [risk](garmin-risk.md). For smoke use token copies so library refresh cannot mutate originals.

Cloud provider/Trainer preference and memory extraction/embedding choices remain independent. Missing key/funding/model/network/auth never silently selects another provider/account. Optional Ollama is not app-owned. Local debug traces may contain private chat/Garmin context and must not enter screenshots/support artifacts; redacted local payload archives are not unrestricted model evidence.

## Lifecycle and local security

Native owns a fresh process group and ephemeral `127.0.0.1` backend, never an unrelated source service. A private random readiness identity plus actual composition/selected DB lease proof precede trainer display; HTTP 200 alone is insufficient. Identity never enters a public URL. Foreign Origin/Host/cross-site requests are refused. Loopback is a single-user operational boundary, not isolation from other same-user processes.

Only local setup has narrow settings/auth IPC. Trainer/remote pages have no settings/auth/native-action privileges; an explicitly admitted smoke trainer may only return correlated closed results; new windows/external navigation are refused. Second launch focuses the existing native instance and ignores arguments, never starts a second writer. Port zero coexists with unrelated listeners. Startup is bounded at 90 seconds; failure shows settings without hidden retry.

Quit drains HTTP/Next work for at most five seconds; owned-group termination is bounded at eight seconds. Auth is cancelled and only native-owned Node/connector/FIT/auth descendants are stopped, not listeners/Ollama/primary processes. Host death closes the pipe and causes bounded child termination; auth also detects pipe EOF. Cancellation is not DB rollback: saved turns/planning writes/checkpoints remain, generation/import/title work may be incomplete. Force-kill/power loss can leave a lease requiring exact ownership inspection. Relaunch reads persisted state.

## Validation and recovery

Routine development smoke is [programmatic-first on real isolated native instances](dev-bridge.md). `npm run smoke:ordinary -- --scratch <canonical-private-task-scratch> --input-file <private-explicit-db-selection.json> --bundle <ordinary-app>` copies two unmodified ordinary bundles outside checkout, validates versioned early native run/artifact/source/boot admission and confines all private state without HOME replacement or normal singleton contact. It captures fixed wide/narrow Trainer/Sync/Profile views with geometry-preserving hide-by-default masks; inspect each image and disclose hidden surfaces/synthetic DOM input. Default invocation remains unchanged and has no installed controller/result grant. The existing debug route remains `npm run smoke:native -- --scratch <canonical-task-scratch> --input-file <private-explicit-db-selection.json>`. It uses populated copies, no provider/Keychain/login or primary mutation, two simultaneous nonactivating instances and actual Goals save/restart/capture. Inspect every sanitized Profile-subtree PNG; capture alone is not evidence. Separately, debug-only `smoke:settings` preserves keyless native Connect/later/cancel/Save/restart and sanitized Garmin subtrees, without credentials or trainer privileges; its current contract cannot run login/MFA/adoption/pickers/Finish or certify ordinary artifacts. Safe task-needed bridge/runner evolution is expected; use the [before-use extension recipe](dev-bridge.md#task-needed-bridge-and-runner-extensions) for missing Settings/Sync/copied-token evidence, not a categorical feature ban. Native private-state ownership, no unattended fresh login/MFA and ordinary-artifact obligations remain binding. Mouse/native input remains last resort for trusted input/drag-and-drop/native dialogs, not routine navigation.

Run `CI=true npm run validate`, `npm run eval:reliability`, `npm run desktop:build`, then `npm run desktop:test:native`. Fresh native tests require assembled resources; build first or assemble `desktop:resources`. Focused settings/UI/Python/native tests cover manual-control absence, preserved exact internal selections, managed private roots, session-bound verified selection and stale polling/MFA/cancel, plus validators/defaults, masking/intents, descriptor safety/atomicity, legacy all-slot adoption/denial/re-entry, private protocol, MFA/rejection/cancel/timeout/late events, no-overwrite publication, env retirement, Next reset, DB admission/origin/lease/resource safety and connector stripping. No skipped/weakened guardrails.

Actual unsigned ARM64 production smoke must run outside checkout on WAL-consistent populated DB/private token copies, with inspected sanitized local screenshots. Exercise settings/advanced fields, private-file save/reload and explicit legacy adoption/denial/re-entry, blank Create/Finish/relaunch and populated Use-existing, partial-commit/cancel/retry, ordinary save/restart-required, admission/quit/relaunch, saved feature parity, available real providers and Garmin token reads. Operator enters any real new password/MFA privately in the local UI; simulated challenge tests never become live MFA evidence. Record exact unavailable evidence. Follow developer-process/epic evidence-first cleanup; no screenshot upload/commit.

Failure recovery: check settings version/privacy and explicit paths, private file storage/migration status, readonly selected-target DB status/integrity/schema and exact other owners; rebuild missing resources/ABI on ARM64. Source CLI diagnostics do not read private settings/legacy Keychain. Do not share private settings/paths/keys/tokens/raw vendor/framework logs. Rollback is a prior compatible desktop build with preserved compatible private state/backups, not automatic downgrade, env import, browser fallback, reset or copy-back. Source delivery grants no primary restart/cutover, installation, release or scheduler-owned worktree deletion.
