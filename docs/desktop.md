# Local macOS desktop runtime

The source-built **macOS Apple Silicon** app is a thin Tauri host with an owned loopback Next.js service. React, HTTP/NDJSON, Next `after()`, guarded tools, SQLite and Garmin import policies remain the application, not a remote website wrapper or Rust domain rewrite. Default launches grant native commands only to the local settings document, never trainer/remote pages. An explicitly admitted isolated ordinary-artifact or debug smoke instance has only its exact-origin correlated-result callback, never settings/auth privileges; see [programmatic smoke](dev-bridge.md).

Unsigned/non-notarized ARM64 builds only: no installer, auto-update, login item or background service. The [release runbook](release.md) owns packaging and publication, and [release records](history/releases.md) hold each published download's identity. The [supported platform boundary](source-beta-readiness.md#supported-boundary) is macOS ARM64; the [Windows x64 alpha](windows.md) is an experimental build outside it.

## Build and run

Build prerequisites: ARM64 macOS, Xcode/Command Line Tools, Rust/Cargo, Node 22/npm and, for the developer build/validation scripts only, Python 3.12. The app itself needs no Python, uv or uvx: Garmin access and activity-file decoding run in its bundled Node. Optional Ollama is external. No software/model installation or Ollama startup is performed by the app.

```bash
npm ci
npm run desktop:build
```

Open `src-tauri/target/aarch64-apple-darwin/release/bundle/macos/Garmin Trainer.app`, including outside the checkout. `desktop:dev` uses the same rebuilt production resources, no HMR/browser dev server. Source edits require rebuilding. Catalog/shared keys can apply live after exact acknowledgment; all other settings still require explicit quit/reopen. Tauri is the sole product launcher. Retained doctor/status/migration/private-terminal-auth tools are non-serving maintenance, not desktop configuration sources.

The native crate enables `custom-protocol` by default so local settings/error HTML works without a backend. Native Settings remains available from the **Settings…** native menu regardless of backend readiness. Startup status is persisted in memory to avoid listener races.

`desktop:build` passes `--no-sign --no-binary-patching`; no codesign/notarization runs. Do not disable Gatekeeper or install/sign to bypass errors. Keep release stripping disabled: Homebrew Rust 1.98 proc-macro metadata failed with release stripping (`E0463`); the supported no-strip build preserves compiler output.

A separate [change-gated nightly profile](validation.md#change-gated-native-nightly)
uses full validation's single backend build, assembler-only `desktop:assemble`,
locked Rust checks/tests and one synthetic `smoke:quick` debug run. It does not run
optimized release packaging or replace ordinary actual-artifact/integration smoke.
Only use assembler-only immediately after a same-input production build; existing
`desktop:resources` still builds then assembles.

### Reproducible resources

`scripts/desktop/runtime-inputs.json` is a finite target map: Node 22.23.4 for `macos-arm64` and `windows-x64`, each with its official archive checksum. Assembly selects the single target matching the native host (any other host refuses), verifies the archive and probes bundled Node/SQLite ABI plus launcher imports. Cargo/npm locks pin their inputs; Tauri direct versions are exact.

Resources include production standalone output/static assets, the pinned production Next custom-server package (without source maps, type declarations, development runtimes, docs, bundle analyzer or the unused `next/og` renderer; Next's optional sharp image optimizer is excluded and images stay unoptimized), native SQLite, the bundled launcher/Zod and the ChatGPT OAuth helper script. The official Garmin reader and its FIT decoder (`fit-file-parser`) are compiled into the server bundle; no Python file or Garmin connector is packaged. Private env/data/keys/logs are never packaged. `provenance.json`, the first-party MIT license, the actual Node license, third-party notice texts and the reviewed source/patch corpus accompany builds; see [redistribution material and release conditions](redistribution.md). Required corpus files enter the resource inventory and release verifier, not just package-license metadata. Metadata is not redistribution authorization. Provenance v2 retains the original whole-source build snapshot separately from conservative build-source/context identity. The full locked `desktop:build` publishes an ordinary-only complete-inventory stamp; the [ordinary driver-reuse contract](smoke/ownership.md#ordinary-build-identity-and-current-driver-reuse) defines its exact external-path set and fail-closed checks. Legacy artifacts require rebuilding, never relabeling.

Resources are immutable: desktop disables ISR disk flushing/image optimization, and bounds memory cache. The trusted build configuration is installed through Next's standalone configuration path and retained across framework env reset; the custom-server wrapper does not forward its direct `conf` option to the router. Provider values never enter that serialized build configuration. Private state/WebView storage stays outside the bundle. The supervisor drains and discards incidental output, accepting only bounded allowlisted startup messages; vendor/framework stdout/stderr are not diagnostics.

## Explicit private-state adoption

**Settings** replaces env-file selection/loading entirely. Upgrades do not import the old pointer or env files. Users re-enter supported settings; originals are retained unchanged for rollback. No cwd/home/adjacent env discovery or generic environment editor exists.

- Genuine first run has Data → Provider → Connect Garmin or continue → Review steps. Explicit **Create new database** uses a visible unused owner-private app-data destination outside source/bundle; a custom destination needs an existing private parent. Bootstrap runs authoritative migrations in memory, then native writes/fsyncs/read-only verifies and exclusively publishes fresh bytes under a pinned parent descriptor/shared target lease. Existing files, sidecars, aliases and unknown leases are never replaced. No writable selected-file migration or initialization WAL is involved.
- **Use existing data** selects a compatible DB using a canonical absolute path. Garmin has Connect/continue/replace-key actions, not directory controls; old unofficial-connector token selections remain inert, unchanged metadata. No aliases, shell expansion, URLs or relative paths. Selected DB will be writable: first quit other owners, evaluate on a disposable populated backup, and obtain separate approval before primary cutover.
- `settings-v3.json` under the canonical platform app-config directory for `com.codexa.garmin-trainer.desktop` stores `{version:3,fields,keys,chatCatalog,garminApiKey?}`: unrelated/legacy extraction fields, private raw OpenAI/DeepSeek/OpenRouter slots, a version-1 chat catalog and the optional Garmin Personal API key (a distinct field, not a chat slot; older builds refuse a file that carries it rather than dropping it). Retired `GARMIN_MCP_*`/`GARMIN_FIT_*_COMMAND` fields from earlier builds are carried forward unchanged as inert metadata and are never editable or forwarded. Entries use durable opaque IDs (not row positions), literal model IDs; valid old optional names remain inert compatibility metadata, preserved on Save but never displayed or edited. Maximum 32 entries, ID 80, model 256 and legacy name 80 characters; malformed legacy names still refuse. Exact duplicate provider/model tuples and invalid legacy compatibility inputs are rejected. Trainer owns a single explicit DB-persisted choice; new catalogs have no configured default. Directory `0700`, file `0600`, current uid, regular single-link bounded (128 KiB) unaliased objects. Descriptor-bound reads and pinned no-follow parent traversal, exclusive staging/fsync and atomic rename protect publication. Pre-existing insecure objects are refused, not chmodded/adopted. This is **plaintext, not encryption**: same-user/privileged processes and backups can read it. No Garmin email/password/MFA or token contents. Never include this document in logs/support/export/Git.
- No history date or hidden date default is needed. **Garmin history → Limit how far back to import** shows a required **Import from** date only when enabled. Off hides/disables the whole date control; off/on drafts preserve its value, while explicit Off-and-Save clears the limit. The literal YYYY-MM-DD editor has no manufactured date: WebKit's empty native date editor can paint today despite an empty value. Invalid saved text remains visible for correction, with calendar/no-future validation and unchanged native authority. Existing valid dates load selected, invalid nonempty dates remain Limited until corrected or explicitly disabled, and blank/missing configuration selects automatic bounded discovery after the next explicit launch. A limit never proves remote inception. Normal settings cover DB, Garmin connection actions and compact provider-grouped Model ID rows with per-provider Add/Remove and shared masked key slots; no default actions. Provider key controls remain mounted through row edits, duplicate/32-entry correction and failure reconciliation. Ollama's chat connection disclosure stays with its group; the shared summary/title selection remains independent of chat and preserved extraction fields. Token paths remain compatible internal configuration, never normal manual controls. No global chat auto/provider selector remains. Memory exposes summary processing On/Off, the shared summary/title model and N. Original extraction/embedding fields stay preserved but hidden/inactive; five executable overrides and optional Ollama chat remain independently configured. Technical/legacy sections and executable editors are removed; complete preserved values remain mounted hidden/inert and persist independently of visibility/disabled state. Summary Off preserves records and the immediate Trainer disable preference; title processing remains independent. The retained native read_memory_status command is setup-only, fixed and identity-bound to the owned backend; it returns version1 active summary metadata, never memory content, embedding health, new probes or provider requests. Its ordinary Settings button/result/timer are removed, without replacement automatic reads. Saved/draft values are not active status; missing/stale observations remain unknown, not provider readiness. Shared application validators/defaults remain authoritative; native invokes bundled validation and readonly DB schema/integrity checks before private settings changes. No connector pin/args/transport/allowlist, port/origin/identity or arbitrary command/env controls are editable. Debug traces remain always enabled by tested policy; no misleading off toggle.
- Eligible first-run **Finish and open Trainer** validates required provider configuration before creation, commits DB/private settings separately, and uses the existing owned-backend readiness path in this session. No cloud probe, automatic login/sync or fallback. Native captures genuine settings absence once; crashed/invalid/unsupported existing installations do not gain first-run authority. Duplicate operations serialize natively. Cancel/quit is bounded; already committed DB/settings/independent tokens remain saved. Explicit retry reconciles exact DB identity or, after settings commit, opens only the committed configuration. After an interrupted DB-only commit/relaunch, explicitly choose that retained file as existing data.
- Ordinary **Save settings** commits first, then live-applies only catalog and all three shared key slots after exact owned-backend boot/generation/revision acknowledgment. Captured work retains its admitted snapshot; the independent explicit Trainer choice is never written or initialized by native activation. No backend/busy/refusal reports saved/not applied; deadlines/disconnect report saved/live outcome unknown, not rollback or unchanged. Reload reconciles exact saved/active metadata without replay; unresolved prior uncertainty refuses another write. Invalid/stale/precommit failures preserve prior state. All other fields remain pending explicit quit/reopen against effective startup inputs. Ordinary Save returns only `{message, restartRequired}`: the notice requires a confirmed durable private commit and an effective field changed by this Save that is still different from active startup. Absent/busy backend requires reopen only for confirmed changed fields. Default-equivalent round trips, repeated/live-only Saves with old pending state and restoration to active do not prompt. Uncertain commit/projection or failed metadata reload suppresses the notice and retains recovery warnings. The local labelled modal focuses OK, contains Tab, dismisses with OK/Escape and returns focus; it never controls the app. Close/reload clears stale presentation; first-run Finish retains its same-session string result and no modal. No hidden start/restart, DB/account switch, Default/Reset, provider probe or fallback.
- Missing/corrupt/unsupported private settings or unavailable required provider keys reopen sanitized actionable settings. Unknown versions are not overwritten/downgraded. Preserve the record for recovery and use a compatible build; do not delete data, relax permissions or fall back to env files.

Presence selects v3 before v2 before v1, including corrupt, unreadable or aliased objects. Unknown/newer formats refuse overwrite/downgrade. Explicit Settings Save from v2 exclusively publishes v3 and indefinitely preserves original v2 bytes; startup derives only a read-only compatibility catalog until that action. Explicit old provider intent survives, including missing-key intent. Old auto projects its configured DeepSeek-first/OpenAI model when determinable, else no default; no continuing chat fallback policy. Catalog edits do not rewrite preserved extraction fields or the restart-only shared summary/title selection. Empty catalogs admit offline views with chat selection required; existing DB admission remains binding, but inactive embedding fields require no embedding key/service. When only `settings-v1.json` exists, validate its allowlisted fields and `SLOT/UUID` account references without querying Keychain; startup reports migration-required and opens setup. This is not blank-install authority. Startup, menu refresh, ordinary Save and Finish never call Keychain, including metadata queries.

Choose **Adopt referenced Keychain keys once** in trusted local setup to read only referenced accounts under legacy service `com.codexa.garmin-trainer.desktop.provider.v1`. macOS may request permission; never bypass refusal or automate its dialog. Adoption serializes with settings/Finish/activation, resolves every unchanged legacy slot, validates the complete intended existing-activation frame through the bundled validator, then exclusively publishes v3 with the reviewed catalog. Optional provider slots must also resolve or be explicitly replaced/cleared; partial retrieval is discarded, never silently omitted or automatically retried. After denial/locked/missing values, privately replace or explicitly clear every legacy configured slot and choose **Save private re-entry without Keychain**. This action makes zero legacy reads. A keyless legacy document follows the same explicit action without secret reads.

Both actions preserve original v1 bytes and **all original Keychain items indefinitely**, even on success; there is no cleanup/deletion API. No env import, broad enumeration, cloud probe or background adoption exists. Cancel before publication leaves legacy authority intact. Rename is the single-document commit/selection point; an interrupted launch reconciles v3 without rereading Keychain. Postrename verification/directory-sync failure reports **committed, durability uncertain**, not rollback or retry permission. Metadata-only reads include a bounded file-identity/mtime/ctime/size revision; whole-form save/adoption compares the loaded revision under native serialization. Stale forms refuse without publication and require reload, including intervening key-only edits. Reload metadata before another explicit action. Concurrent changed targets refuse publication; no existing v3 is overwritten by migration. Deleting/downgrading v3 is unsupported recovery. Preserve it and original v2/v1/Keychain inputs; use a compatible catalog build/forward fix, not forced legacy fallback.

Reads return only fields/storage/slot status, never saved values/account payloads. Each keyed provider has one password-style field: a fixed placeholder mask indicates configured presence without putting a saved value or sentinel in the input. Untouched/focused fields remain unchanged; typing/pasting creates replacement intent with only newly entered text. Backspace/Delete against saved presence, or deliberately emptying its replacement, marks clear. An absent slot edited then emptied stays unchanged. Accessible status distinguishes configured, absent, pending replacement/removal and unavailable metadata. Save, Finish and explicit adoption/private re-entry share the intent converter; submit/error/cancel/close clear replacement drafts without inventing deletion. Replacement retries require fresh entry; failed refresh disables key editing and refuses writes. Explicit intents affect only the active private document; native storage/revision rules remain unchanged and only catalog/shared keys can apply live after exact acknowledgment. Ordinary writes stage a complete replacement and preserve prior bytes on precommit failure; only the acknowledged catalog/shared-key subset can apply live; all other fields remain restart-only. For rollback, preserve v3 and original v2/v1/Keychain recovery inputs plus compatible data/backups. Use a compatible build or forward fix; never overwrite/downgrade settings or delete originals. Source revert grants no private cutover.

Before replacing old catalog inputs, native Save retains immutable private `selectionCompatibility:{database,catalog}` for the original DB. First overwrite of old v3 exclusively archives its exact bytes in `settings-v3-before-single-choice.json`; v1/v2 originals remain unchanged. Authored catalog defaults are cleared, including deletion of a former default row without reassignment. The compatibility catalog is not exposed to the renderer and seeds only that matching DB once; changing to a new DB does not inherit another DB's old default. Original v3 archive conflict or uncertain preservation refuses publication. Older builds reject the additive field; preserve it and use a compatible build/forward fix, not downgrade/deletion.

At startup native sends validated catalog metadata, chat keys and the Garmin key in **one bounded private stdin frame** (activation v3 carries private selection compatibility; old v2/v1 remain supported) for its owned Node child, never argv, inherited secret environment, a generated env file, renderer readback or URL. Internal backend environment remains an adapter only. The pipe stays open after the frame for parent-death/liveness. Live Save uses only fixed authenticated `/__desktop/live-settings` POST/GET on that owned port: browser Origin/Sec-Fetch requests denied, closed version1 projection, 96-KiB bound, monotonic generations, two-second receive/three-second native deadline and exact acknowledgment after atomic process-shared publication. Missing slots delete credentials, never retain ambient values. The Garmin key never travels on live Save: native keeps a fingerprint of the startup key and reports a changed key as pending explicit quit/reopen. The saved compatibility catalog remains a frozen startup input, not part of the live projection; no whole-config reload occurs. Next's reset retains the validated snapshot; DB/identity checks fail closed if it changes. The backend installs the Garmin key as a process-owned capability, never environment. Validated backend adoption sets umask `077` before runtime work, independent of a permissive GUI launcher mask; new descendant files/directories are owner-private from creation, and existing files are not chmodded/adopted.

Readonly existing-file/schema/integrity checks precede ordinary DB construction. Missing/corrupt/old/unsupported DBs are refused, never created/migrated by ordinary startup or existing selection. Only explicit eligible first-run Create new initializes a fresh target; it is not an upgrade/adoption path. Explicit backed-up source migration on a stopped approved target is separate. Source/desktop share `<database>.trainer-writer`; macOS also refuses another process holding the DB open, including older backends without a lease. Unknown/stale leases are never stolen. Inspect the exact owner; never kill listeners or delete a live lease to force admission.

Last-active conversation selection, saved chat, Profile, memory, Trainer preference and general/original/latest weekly documents remain in the selected SQLite DB. ### Schema upgrades

Each schema version is additive and refused by older builds; startup and **Use existing data** never migrate a selected database. To activate a newer schema on real data, separately approve the exact DB/settings target, make and integrity-verify a WAL-consistent pre-upgrade backup, rehearse the explicit process-env migration on an independent populated disposable copy, stop every owner, migrate the stopped target, then check integrity, foreign keys, version and preserved state before a controlled reopen. Recover with a compatible forward fix, never a downgrade, older writer or blind backup copy-back. Per-schema details are in the [schema activation history](history/schema-activations.md).

Native alone persists version2 protected companion credentials, stable host identity, one active registration and rotating tokens. Unsupported private records preserve originals and leave unrelated API-key/local routes usable.

Connection commit, catalog Save and backend acknowledgment remain distinct. Explicit Save also projects saved subscription availability. ## Integrations and GUI execution

The cleared backend environment has a system-only search path (`/usr/bin:/bin`); the product launches no external tool for Garmin. Garmin reads are read-only HTTPS requests from the backend to the fixed official Personal API origin, with activity files decoded in-process. Missing or rejected keys and network/service/rate-limit failures degrade Garmin actions, not offline saved views; guidance appears at the requested action and points to native Settings. Startup, Settings reads and local navigation never contact Garmin; **Sync → Verify connection** is the explicit check.

Saved unofficial-connector selections from earlier builds show **Reconnect needed**; their token files are never read, refreshed, moved or deleted, and nothing falls back to them. **Key saved** means saved configuration, not current validity/expiry. Explicitly choose **Connect Garmin** or **Replace Garmin key** in trusted native Settings and paste a Personal API key created in Garmin Connect; never enter it in trainer chat. Back/Cancel/close discard the key draft and preserve the saved connection and provider drafts. Chat and saved/offline history remain available without Garmin, but fresh Garmin data requires a working key. Garmin key entry is local native Settings only, never model/HTTP/trainer access.

The key field follows the provider-key presence/intent contract: masked presence, untouched unchanged, typed replacement, explicit deletion clears on Save; blank or mask never becomes key data. A fixed native command opens Garmin's key-creation page in the system browser; the app never automates or observes that session.

Save/Finish validate the key's shape only (printable, bounded, not a placeholder), never its remote validity. A saved key applies only at explicit reopen; Save never changes a running import's account.

Garmin's Personal API is documented for individual users, not commercial multi-user services. See [Garmin connection](garmin-auth.md) and [risk](garmin-risk.md). Smoke uses an authored loopback stand-in admitted only through isolated-run ownership, never real keys.

Cloud provider/Trainer preference and memory extraction/embedding choices remain independent. Missing key/funding/model/network/auth never silently selects another provider/account. Optional Ollama is not app-owned. Local debug traces may contain private chat/Garmin context and must not enter screenshots/support artifacts; redacted local payload archives are not unrestricted model evidence.

## Lifecycle and local security

Native owns a fresh process group (Windows: a kill-on-close Job Object, see [Windows mechanisms](windows.md#windows-mechanisms)) and ephemeral `127.0.0.1` backend, never an unrelated source service. A private random readiness identity plus actual composition/selected DB lease proof precede trainer display; HTTP 200 alone is insufficient. Identity never enters a public URL. Foreign Origin/Host/cross-site requests are refused. Loopback is a single-user operational boundary, not isolation from other same-user processes.

Only local setup has narrow settings/auth IPC, including optional subscription administration. The only new external destination is the fixed official ChatGPT usage page; this is not a generic URL opener. Trainer/remote pages have no settings/auth/native-action privileges; an explicitly admitted smoke trainer may only return correlated closed results; new windows/external navigation are refused. Second launch focuses the existing native instance and ignores arguments, never starts a second writer. Port zero coexists with unrelated listeners. Startup is bounded at 90 seconds; failure shows settings without hidden retry.

Quit drains HTTP/Next work for at most five seconds; owned-group termination is bounded at eight seconds. Only native-owned Node descendants are stopped, not listeners/Ollama/primary processes. Host death closes the pipe and causes bounded child termination. Cancellation is not DB rollback: saved turns/planning writes/checkpoints remain, generation/import/title work may be incomplete. Force-kill/power loss can leave a lease requiring exact ownership inspection. Relaunch reads persisted state.

## Validation and recovery

Routine development smoke is [programmatic-first on real isolated native instances](dev-bridge.md). `npm run smoke:ordinary -- --scratch <canonical-private-task-scratch> --bundle <ordinary-app>` copies two unmodified ordinary bundles outside checkout, validates versioned early native run/artifact/source/boot admission and confines all private state without HOME replacement or normal singleton contact. It captures fixed wide/narrow Trainer/Sync/Profile views with geometry-preserving hide-by-default masks; inspect each image and disclose hidden surfaces/synthetic DOM input. Default invocation remains unchanged and has no installed controller/result grant. The existing debug route remains `npm run smoke:native -- --scratch <canonical-private-task-scratch>`. Both default to [authored synthetic input](smoke-inputs.md); optional private input requires a current exact standing/one-off grant, not new approval solely for a ticket change. They use populated copies, no provider/Keychain/login or primary mutation, two simultaneous nonactivating instances and actual Goals save/restart/capture. Inspect every sanitized Profile-subtree PNG; capture alone is not evidence. Separately, debug-only `smoke:settings` preserves keyless native Connect/later/cancel/Save/restart and sanitized Garmin subtrees, without credentials or trainer privileges; its current contract cannot run login/MFA/adoption/pickers/Finish or certify ordinary artifacts. Safe task-needed bridge/runner evolution is expected; use the [before-use extension recipe](smoke/protocol.md#task-needed-bridge-and-runner-extensions) for missing Settings/Sync/copied-token evidence, not a categorical feature ban. Native private-state ownership, no unattended fresh login/MFA and ordinary-artifact obligations remain binding. Mouse/native input remains last resort for trusted input/drag-and-drop/native dialogs, not routine navigation.

Run `CI=true npm run validate`, `npm run eval:reliability`, `npm run desktop:build`, then `npm run desktop:test:native`. Focused settings/UI/Python/native tests cover manual-control absence, Garmin key presence/intents, reconnect-required status, retired-field preservation, startup-only key activation and live-apply exclusion, validators/defaults, masking/intents, descriptor safety/atomicity, legacy all-slot adoption/denial/re-entry, private protocol, env retirement, Next reset, DB admission/origin/lease/resource safety and product exclusion of connector/Python/external tools.
