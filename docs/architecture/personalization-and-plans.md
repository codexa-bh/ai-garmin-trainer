# Architecture: personalization, weekly plans and Training Plan

Part of [architecture](../architecture.md). User behavior belongs to [memory](../memory.md), [summary](../cross-chat-summary.md), [Training Plan](../training-plan.md) and [weekly KPIs](../weekly-kpis.md).

## Personalization application and adapters

Summary policy lives in `memory`; `db/summary-storage` owns eligibility, leases, CAS, coverage, manual controls and spend. `summary-import` seals reviewed source selections/dispositions; `summary-rebuild` inventories/stages originals and supplies candidates to the same writer, not another engine. Composition binds native configuration to reviewed Start/foreground continuation. Only ordinary launcher lifetime schedules private ticks; passive reads do not generate. Only a complete validated replacement publishes, preserving suppression/manual/stable-pin rules. Unproven eligibility after prior Clear is conservatively fenced.

Pure `model-settings/summary-selection` decodes the independent shared summary/title choice; `memory/summary-configuration` captures identity/catalog/connection/keys without Trainer preferences. Provider refusal never substitutes a model. There is no application monetary/attempt cap or capacity/pricing qualification registry. Chat owns replay/local compaction and sealed summary consumers, not a second global-memory producer. Null summary and explicit legacy/unavailable mode are valid; unknown models are never silently substituted.

Memory management follows `api/memory → composition → management/application`. Legacy `MemoryPorts` supplies synchronous semantic storage, embeddings, extraction, identity, clock and a secret-free snapshot. Pure ranking/extraction policy has no SQL/env/HTTP/SDK/composition imports, including types. These stores are management-internal, not ordinary-chat retrieval/ingestion entrypoints.

The SQLite adapter owns row/vector/source serialization, upserts, expiry and the 200-row candidate cap. Embedding/extraction adapters own transport, timeouts, normalization, unchanged SHA256 identities and tool-disabled legacy generation. Shared-key changes rotate the lazy current store while in-flight work retains its snapshot. Settings writes precede reset/reload. Health never migrates; lazy legacy migration precedes ingestion/retrieval/enabled listing, writes its marker only after all rows, retains earlier writes on failure and adds no retry.

`profile/application` owns normalization/read/save through synchronous `ProfileStorage`; its repository owns serialization/read-after-write. Retired proposal/confirm/reject/forget facades are not supported APIs; legacy rows, vectors, schema and markers remain. HTTP preserves malformed-body/status behavior and adds no Profile error catch. [Title ownership](backend-roles.md) is independent of summary On/Off and Trainer choice.

Tests: `personalization-application`, `personalization-dependencies`, `personalization-wiring`, `sqlite-memory-adapter` and existing Profile/memory/chat suites. Migration and privacy decisions follow the product guides, not historical refactor no-op statements.

## Weekly plans and reviews

`weekly/{contracts,calendar}` owns civil Monday identity, timezone validation and DST-aware intervals. `weekly/application` owns bounded documents, immutable original/latest separation, as-of reviews and guarded synchronous `WeeklyStore` saves. Composition lazily binds SQLite, clock and IDs. Weekly artifacts/proposals participate in upgrade backup detection and survive chat/Profile/Garmin deletion.

Tools consume complete prior-pass reads. General Plan and weekly bundle each have one save attempt per turn, including failure/uncertainty; focused KPI and narrative `kpiChanges` share the weekly attempt and transaction. Saves check current-turn authority, calendar/content/privacy and unchanged full snapshots. Review/next-plan can commit atomically; General Plan is separate. Actual prior successes remain disclosed after later failure. Legacy proposals remain stored but are not model-visible, replayed or automatically applied. Debug/grounding contain metadata, not document bodies. [Coaching](../coaching-instructions-and-sources.md#weekly-planning-and-review) owns intent, including no-save; there is no consent classifier or injection-proof guarantee.

`weekly/{kpi-contracts,kpis}` owns stable targets/assessments; `weekly/measurements` owns recipe verification, coalescing and conditional publication; `analytics/recipe-execution` is its isolated readonly adapter. [Weekly KPIs](../weekly-kpis.md) owns exact scoring, measurement, refresh, migration and reviewed-maintenance contracts. UI and tools use the same `kpiActual`/latest-score projections, not renderer inference. No narrative parsing, automatic historical rescoring or app-authored coaching rubric is implied.

`/api/weekly` GET is readonly detail/paged summaries. Its existing `refresh-current-week` POST runs current-plus-previous-week measurement refresh and returns both statuses/combined failures. Chat supplies IANA timezone; legacy callers get an explicit server-local fallback. Shell-owned `use-weekly` guards generations/date-zone rollover; [dashboard](dashboard.md) owns navigation and refresh behavior. Tests: `weekly`, `weekly-ui`, measurement/KPI suites and chat/tool/production ownership checks.

## Training Plan application and adapters

`training-plan/{contracts,limits,policy,snapshot,edits}` owns the singleton, normalization, review timing, complete evidence/privacy and original-text edits. `application` consumes synchronous `TrainingPlanStore` plus clock; composition lazily binds SQL. Manual save normalizes/persists/reads back. Guarded tool save reads, validates, compares and writes without yielding. Manual writes may save documents the tool cannot read; they do not acquire tool authorization assumptions.

The initial whitespace-compacted 2200-character preview is **incomplete**. `getTrainingPlan` validates the complete document against existing 32000-character/title bounds and preserves Markdown. Latest complete read reaches subsequent planning and final synthesis outside the generic 1800-character preview. Grounding/debug retain metadata, not read content/save arguments. Unsupported structural snapshots fail closed; user-authored key/path-like prose stays complete untrusted data, not a credential read, and must not be censored into an incomplete overwrite.

Existing-plan tool writes require a complete snapshot seen by a **prior planner pass**, compared with current state before synchronous persistence. Mutually exclusive `edits`/`contentMarkdown` select exact unique non-overlapping edits versus full replacement. Apply edits to original text, preserving unmentioned content/omitted title. Choosing targeted edits versus explicit creation/whole-document replacement is planner policy, not an extra permission model. Rejections disclose structural reasons, not raw errors; uncertain persistence requires inspecting saved state before retry. No proposal wrapper, mandatory preview/confirmation or age-triggered background write is required.

Legacy `stale`/`staleAfterDays` means optional review after more than 60 elapsed days, not invalidity. Unknown revision dates establish no age. HTTP retains aliases, lengths/statuses; repository compatibility functions delegate inward. No inner framework/SQL/SDK/composition imports. Tests: `training-plan-application`, `training-plan-dependencies`, `training-plan-wiring` plus repository/route/evidence/orchestrator coverage.
