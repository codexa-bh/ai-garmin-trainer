# Additional Garmin evidence and its explicit history backfill

Explicit official Sync imports additional evidence beside the existing activity and daily-health facts. The trainer reads detailed comparisons through guarded SQL/math; bounded activity evidence also reports individual snow run/lift counts, measured metric sums/counts and coverage without GPS. This page owns the field/coverage contract and explicit maintenance runbook. Schema 29 introduced the original eight groups; additive schema 30 adds individual snow splits and independent coverage. Older builds refuse schema 30; selected existing databases never auto-migrate.

## Field and coverage contract

| Group                       | Relation (join)                                                                                           | Meaning and units                                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sleep sub-scores and timing | `daily_sleep_detail`, `daily_sleep_score_component` (date → `daily_health.date`)                          | Garmin's sleep date. GMT epoch ms plus source-local wall clock and the offset from the source's own timestamps, never the host timezone. Components `overall/deep/light/rem` carry a 0–100 value. `total_duration/stress/awake_count/restlessness` carry a qualifier and optimal range only, with no invented score. Feedback and insights are Garmin enum codes; free text is dropped. |
| HRV baseline                | `daily_hrv_detail` (date)                                                                                 | Weekly average, best 5-minute night value and Garmin's personal baseline bounds in ms (nightly value/status stay in `daily_health`). These are Garmin evidence, not app thresholds.                                                                                                                                                                                                     |
| VO2 max                     | `vo2_max_reading` (date + branch `generic/cycling/rowing`)                                                | Sparse dated measurements in ml/kg/min, rounded and precise, with source sport when supplied. Never a daily series and never forward-filled.                                                                                                                                                                                                                                            |
| Body Battery                | `daily_body_battery`, `body_battery_event` (date); `activity_extra_metrics.body_battery_delta` (activity) | Daily min/max/charged/drained/latest and the source's end-of-day value (latest is not end of day). Events carry a signed impact, keyed by type + GMT start + duration. Events are linked to an activity only when Garmin names one, never by time. The activity delta is signed, not a level. Range data only: no single-day wake/sleep reads.                                          |
| Stress breakdown            | `daily_stress` (date)                                                                                     | Bucket durations in seconds (source milliseconds converted). Fractions are 0–1 only when the row's proportions agree with its own durations; otherwise they are null. Activity and uncategorized time are not high stress.                                                                                                                                                              |
| Per-lap HR zones            | `activity_lap_hr_zone_time` (activity + lap number + bucket)                                              | From the activity file's lap-referenced `time_in_zone`, joined by the lap's own FIT `message_index`. Bucket 0 is below zone 1, 1–5 are zones, 6+ are above, each with that file's own boundaries/method/max/resting HR. Missing or duplicate references make the activity's lap zones unavailable. Session totals in `activity_hr_zone_time` are unchanged; never add the two.          |
| Running dynamics            | `activity_extra_metrics` (activity); `activity_lap.fit_*`                                                 | List cadence is steps/min and stride is centimetres. FIT cadence is **cycles/min** including the fraction (a stride for foot sports, a revolution for cycling) plus total cycles. FIT oscillation/step length are converted from mm. Ground-contact/oscillation/ratio/balance/grade-adjusted speed exist only when a sensor recorded them.                                              |
| Snowboard splits            | `activity_split_summary` (activity + split type)                                                          | Per-type **totals** for `SKI_RUN_SPLIT/SKI_LIFT_SPLIT/ASCENT_SPLIT/DESCENT_SPLIT/TRANSITION` from the activity list: count, total duration/distance, best single split. They are not individual runs.                                                                                                                                                                                   |

| Individual ski/snowboard runs and lifts | `activity_snow_split` (activity + stable split key) | Individual measured FIT message 312, `run` versus `lift`: UTC measured start/end; elapsed/timer/moving seconds; distance, ascent/descent/start elevation metres; average/max/signed vertical speed m/s. Missing fields stay null, including moving time/end time; zero is valid and elevation may be negative. Endpoint degrees are GPS and only for bounded explicit route questions, never default activity summaries. Source is `garmin_official_fit`. |

`garmin_data_coverage(data_group, subject_type, subject_id, status, reason)` records, per group and date/activity, `populated`, `empty` (the source replied without it), `unavailable` (the source cannot supply it, for example no original file or stored laps that differ from the file) or `failed` (the read failed). **No row means not yet imported or backfilled**, which is unknown, not empty or zero. The original groups retain `populated` on later failed/empty/unavailable reads. Independent `snow_run_lift_splits` instead reports the **latest attempt**, even when useful prior children survive: read rows plus coverage together, never call retained rows a complete fresh read.

Foreground Sync derives these groups from the replies it already reads. Daily groups come from the same 31-day ranges, plus one VO2 range read per planned block. List extras come from the same activity pages, and lap evidence from the single FIT decode per activity. Scalars merge with coalesce, so a missing value never erases a stored one. Sleep components merge per component. Event and per-type summary sets are replaced only when their source list was returned. A detail refresh replaces lap zones with its lap set. Individual split sets require one FIT session and unique valid source message indexes (0–4095); key `index:N` is independent of file order. Display by start_time then message_index; source_order retains file order. Missing/duplicate index, unknown type, multisession, reversed interval or more than 2,000 split messages makes the entire set unavailable, never truncated/partially authoritative. Complete nonempty refreshes reconcile removed keys and merge surviving null metrics; empty/unavailable/failed reads preserve useful prior rows. Original decode failures are failed, not no-file. Splits import independently of stored laps. No verified lap/HR reference is available (`no-proven-lap-link`): count equality/order/start proximity never grants a join or HR allocation. Aggregate split and lap-zone sets separately before an activity join; never add individual and summary totals or count lift ascent as athlete effort. KPI recipe freshness includes all split facts and latest coverage. Garmin deletion removes all these relations and coverage.

## Explicit history backfill

Existing history needs **fresh official reads**: earlier archives do not contain these fields. `npm run backfill:garmin-extra` is an explicit maintenance command, never run by startup, Sync or Settings. It shares the official reader and normalizers but by default writes the original additional relations, coverage and its own `garmin_extra_backfill` checkpoint. `--snow-only` selects only the independent individual-split operation described below, not those default phases. It never changes existing activity/daily-health/lap facts, sync/history/finality checkpoints or other domains. It never creates days or activities: daily groups are read only for stored `daily_health` dates and list/lap evidence only for stored activities. Lap evidence is written only when the stored laps match the file's laps (count, number, start instant within 2 s); otherwise the activity's lap zones are `unavailable`.

### Preconditions (every invocation needs current authority)

1. Exact approved target, stopped app and every other writer stopped; the shared writer lease must be acquirable. Never kill processes or delete a lease to force admission.
2. A verified, WAL-consistent recovery backup made before any write (`npm run db:migrate` makes one for an upgrade; otherwise use an SQLite online backup and verify integrity, FKs and schema).
3. Explicit migration to schema 30 and integrity verification: `DATABASE_PATH='/exact/approved.sqlite' npm run db:migrate`. The backfill refuses any other schema.
4. A rehearsal of the same command on a disposable copy of the same target. For individual snow history, it must cover the **full stored snow selection and historical range**, not samples or a shortened date window. Present verified backup/rehearsal/preservation/coverage and request bounds, then obtain a fresh explicit primary migration/backfill go. Start, source merge and T0352 authority are not that go. Private data/key/service access and primary stop/build/activation/reopen each require exact current authority.

### Run

```bash
# Key on stdin only: never argv, environment, logs or chat.
DATABASE_PATH='/exact/approved.sqlite' npm run -s backfill:garmin-extra -- \
  --from 2024-07-01 --to 2026-11-19 [--max-requests 150] [--max-seconds 600] < private-key-input
```

Requests are serial, at least 1 s apart, and capped per invocation (defaults 150 requests/600 s; maxima 1000/3600). Phases run in order: daily ranges in 31-day blocks (summaries, sleep, HRV, Body Battery and VO2), activity pages in 90-day windows padded one day each side, then one FIT download per activity. Already-settled subjects (any non-`failed` coverage) are skipped, so repeats cost no reads and retry only failures.

Each batch's data and checkpoint commit in one transaction. A crash leaves neither, and the next invocation replays that batch idempotently. The checkpoint binds the contract, schema, target (hash of the canonical path) and date bounds. A mismatched or corrupt checkpoint refuses without being rewritten. Cancellation (SIGINT/SIGTERM), the request/time budget, authentication failure and HTTP 429 **stop** with durable progress. Isolated service/protocol failures mark only that batch's groups `failed`. Three consecutive failures stop the run.

**Account guard.** The Personal API exposes no stable account identity to the reader, so the backfill checks evidence before writing. Stored activities in each window must recognisably reappear in the fresh list, and stored daily steps must match where both exist. Otherwise it refuses with `account-or-target-mismatch` and writes nothing for that batch.

Output is one JSON line containing `status` (`completed|stopped|refused`), a closed reason, pass/phase, counts (dates/windows/details read or failed, `lapsMismatched`, `localNotInSource`, `sourceNotLocal`), requests by endpoint family, per-group coverage counts, integrity and FK results. It never contains the key, IDs, measurements, payloads or paths.

### Snow-only individual history

Use the same command with `--snow-only --from <full-history-start> --to <full-history-end>` and private stdin key, under the preconditions above. This writes only `activity_snow_split`, latest `snow_run_lift_splits` coverage and `garmin_snow_split_backfill`. It never rewrites laps, streams, zones, core/list/daily facts, completed T0352 coverage/checkpoint or normal Sync/finality/history state. Selection is the stored closed skiing/snowboarding sport set (resort/backcountry/alpine/cross-country/skate variants included), deterministically ordered across the supplied full range; it never invents candidates.

Checkpoint binding includes contract/schema/target (canonical path + device/inode hash), full candidate identity/order and date range. Changed/foreign/corrupt bindings refuse, including after completion: reconcile explicitly, never clear state to force admission. Each pending subject must reappear in fresh padded local-date activity pages (at most 20 pages per day) before its FIT read, or admission refuses as account/target mismatch; no stable account ID is invented. Listing is admission only, not persisted list evidence. One FIT download/decode per pending subject per attempt supplies all split fields. All existing serial/request/time limits apply. Output adds selected/skipped/processed/failed/listReads/fitReads counts. Settled nonfailed new coverage skips repeat work with no requests; absent/failed new coverage remains pending regardless of settled old lap coverage. Data/coverage/checkpoint commit together. Cancellation/budget/auth/429 stops; read/store/invalid-original failures stop with visible failed/pending coverage and no automatic retry. Missing original is unavailable, successful no messages empty. Each distinct resume requires reconciled effects and fresh scoped authority.

### Recovery

A stopped or refused run leaves the target consistent. Inspect the result and coverage, then continue only under current authority with the same bounds; never reset or edit the checkpoint to force rereads. A source revert is not a schema rollback: keep the recovery backup and newer writes and use a compatible forward fix or a separately reconciled restore. Reopen only a schema-30-compatible app within explicit reopen authority. Preserve genuine pre-write recovery backups (not expiring rehearsal scratch), originals/settings/tokens and newer writes; never automatically restore. Verify full-selection new coverage, zero unresolved failed/pending subjects, integrity/FKs and unchanged original/unrelated/checkpoint facts before declaring primary delivery complete.
